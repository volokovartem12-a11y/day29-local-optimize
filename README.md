# День 29. Оптимизация локальной LLM

Локальная модель из дня 28 (`qwen2.5:7b` в Ollama) настраивается под конкретную задачу: **ответы по документации проектов челленджа с обязательными дословными цитатами** (RAG, поиск полностью локальный — bge-m3).

Итог — модель Ollama **`advent-rag`**: выбранная по замерам модель с зашитыми параметрами и системным промптом (`Modelfile`).

## Что оптимизируется

Профили в `profiles.json`. Каждый следующий меняет одну группу настроек, чтобы был виден вклад каждой:

| Профиль | Что меняется |
|---|---|
| `baseline` | **до оптимизации** — настройки дня 28: temperature 0.2, окно 8192, лимит ответа 900, промпт v1 |
| `params` | **параметры**: temperature 0 + seed 42 (детерминированность), top_k 20 / top_p 0.8, repeat_penalty 1.05, окно 6144 (меньше памяти под кэш контекста), лимит ответа 600 |
| `prompt` | **промпт под задачу** (v2, `prompts.py`) + **JSON-схема** ответа в Ollama |
| `q8_0` | **квантование** Q8_0 — точнее, но вдвое больше памяти |
| `q3_K_M` | **квантование** Q3_K_M — меньше памяти и быстрее, но может терять точность |
| `ctx4096` | проверка нижней границы окна (только для сравнения, в итог не выбирается) |

Базовая `qwen2.5:7b` — это квантование Q4_K_M, так что сравниваются три уровня: Q3_K_M / Q4_K_M / Q8_0.

**Почему промпт v2 именно такой.** В дне 28 у локальной модели были две проблемы: она пересказывала своими словами (ключевые элементы ответа нашлись в цитатах лишь в 46% случаев) и почти в половине ответов цитаты не проходили проверку с первой попытки. Поэтому в v2: сначала дословные цитаты, потом короткий ответ только из них; цитата — одна строка без склейки; ответ 1–3 предложения; один пример на чужой базе; JSON-схема, в которой поле `quotes` идёт первым — модель генерирует его раньше ответа.

## Как сравнивается

- Поиск выполняется **один раз** на вопрос, контекст одинаков для всех профилей — меняется только модель и её настройки.
- Два набора вопросов: основной (14, из дней 22–28) и **новые** (9, `heldout_questions.json`) — они не участвовали ни в калибровке, ни в написании промпта. Так видно, что оптимизация не подогнана под основной набор.
- Перед каждым профилем все модели выгружаются из памяти — холодная загрузка и память меряются честно.

| Что | Метрики |
|---|---|
| **Качество** | покрытие обязательных фактов; ключевые элементы ответа в цитатах; ответы «мимо» (ответила, но ни одного нужного факта); проверка цитат с первой попытки; правильный отказ, в т.ч. стресс-тест; обрезанные ответы и контекст. Сводный индекс: 0.4·покрытие + 0.25·элементы в цитатах + 0.15·первая попытка + 0.2·отказ |
| **Скорость** | время ответа (медиана, p90), токены/с, время чтения контекста, длина ответа, холодная загрузка |
| **Ресурсы** | размер файла модели, память под загруженную модель и её доля на видеокарте (Ollama `/api/ps`) |
| **Стабильность** | совпадение статуса и разброс покрытия/времени между прогонами, сбои |

**Выбор итога:** наибольший индекс качества по всем вопросам; если несколько профилей отличаются меньше чем на 0.02 (это шум на таком числе вопросов), берётся более быстрый, затем более лёгкий. Результат — `optimized_profile.json` и `Modelfile`, из которого собирается `advent-rag`; затем `advent-rag` проверяется на тех же вопросах (профиль `final`), чтобы убедиться, что параметры из Modelfile дают тот же результат.

## Запуск (PowerShell)

```powershell
cd "C:\Users\Администратор\Desktop\day29-local-optimize"
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

Скрипт сам: поставит зависимости, запустит Ollama, скачает недостающие модели (`qwen2.5:7b-instruct-q8_0` ≈ 8,1 ГБ, `qwen2.5:7b-instruct-q3_K_M` ≈ 3,8 ГБ), соберёт индекс, прогонит профили, соберёт `advent-rag` и проверит её. Отчёт — `output\report_day29.md`.

Другие режимы:

```powershell
.\run.ps1 -Runs 1                                    # быстрее
.\run.ps1 -Profiles baseline,params,prompt           # без скачивания других квантований
.\run.ps1 -Mode ask -Query "Какие команды есть в чате проекта дня 9?"
.\run.ps1 -Mode ask -Query "..." -Baseline           # тот же вопрос модели до оптимизации
.\run.ps1 -Mode chat
.\run.ps1 -Resume                                    # продолжить прерванное сравнение
ollama run advent-rag                                # оптимизированная модель как обычная модель Ollama
```

## Что проверено и что нет

- **Проверено на имитации Ollama** (модели заменены заглушками): весь код — передача параметров и JSON-схемы, учёт обрезанных ответов (`done_reason = length`) и контекста, замер памяти через `/api/ps`, выгрузка моделей, скачивание, выбор лучшего профиля, `Modelfile`, проверка `advent-rag`, продолжение прерванного прогона.
- **Не проверено — покажет ваш компьютер**: реальное качество, скорость и память каждого профиля и сам `run.ps1`. Цифры брать только из реального прогона.

## Ограничения

- Вопросов 14 + 9: разница меньше 2–3 пунктов — шум.
- Покрытие фактов — проверка по ключевым словам, смысловых ошибок она не видит.
- Ollama не отдаёт загрузку видеокарты в процентах — память берётся из `/api/ps` (модель + кэш контекста).
- Если ответы не помещаются в `num_predict` или контекст в `num_ctx`, это видно в столбцах «Ответ обрезан» / «Контекст обрезан»; такие профили штрафуются при выборе.
